# AI 模式 · 批量删除

[繁體中文](README.md) ｜ **简体中文** ｜ [English](README.en.md)

在 Google AI 模式（`google.com/search?udm=50` / AI 模式页）左侧「最近的对话」列表上，
画出勾选框、支持全选，然后一次把勾起来的对话串通通删掉。

免费、没有数量上限、数据不出你的电脑。没有后端、没有账号、没有 token。

---

## 为什么做这个

市面上那类扩展把「批量删除」锁在付费墙后面（免费只让你删 5 个），
但说穿了它做的事就是：帮你连续点开每一行的 `⋮` → 删除 → 确认。
这件事用一个 content script 就能做完，不需要付钱。

---

## 安装（加载已解压的扩展程序）

1. 把整个 `ai-mode-bulk-delete` 文件夹放到你不会误删的地方
2. 打开 Chrome，地址栏输入 `chrome://extensions`
3. 右上角把 **开发者模式** 打开
4. 左上角按 **加载已解压的扩展程序**，选 `ai-mode-bulk-delete` 这个文件夹
5. 钉选右上角的图标（可选）

> 每次启动 Chrome 会跳「请停用开发者模式扩展程序」的通知，按 **保留** 就好。

装完 **重新刷新** 已经开着的 Google 页面，否则 content script 不会注入。

---

## 使用

1. 到 Google AI 模式，把左侧「最近的对话」展开
2. 右边会出现面板（也可以按工具栏图标开关）
3. 用面板勾、或直接点页面上每一行左边新出现的勾选框
4. 按 **删除所选** → 确认 → 等它跑完

> 页面上的勾选框会先帮每一行让出一条左边留白（只改 `padding-left`），
> 所以框子永远不会压到标题文字；把「页面勾选框」取消勾选就会把间距还原。
> 这跟屏幕分辨率或系统缩放比例无关，全部用 `getBoundingClientRect()` 算，是 CSS px。

> **同名对话串**（例如两个都叫「Browser Harness」）会被当成两行各自处理：
> 勾选用的是 Google 每一行的 `data-thread-id`，不是标题，
> 所以「全选」的数字会跟行数一致，删除与导出也是一行对一行，不会漏掉第二个。

面板上的东西：

| 按钮 | 作用 |
| --- | --- |
| 全选 / 反选 / 清除 | 选择操作 |
| 重扫 | 手动重新抓一次列表 |
| 校准 | 抓不到列表时，点一下任一对话串教它认 |
| 诊断 | 把目前抓到的 DOM 信息复制到剪贴板（回报问题用） |
| 删除所选 | 开始批量删除（跑的时候会变成「停止」） |
| 导出列表 | 只把勾选的标题存成纯文本列表（删之前想留个记录很方便，不会产生 .md） |
| 导出内容 | 把勾选的对话串「内容」整篇抓下来，存成 纯文本 / JSON |
| 加载全部对话串 | 自动往下滚，把延迟加载的旧对话串也捞出来 |

「间隔」是每一笔之间的等待毫秒数。默认 700ms，调快（例如 300）会快很多，
但如果 Google 那边反应慢，可能会有几笔失败，失败的会留在列表里让你重跑。

### 界面语言

面板上的 **语言** 下拉可以切换 **繁體中文 / 简体中文 / English**，
选完会立刻换、也会记住。导出的文件标头、log、对话框都跟着这个设置走。

## 导出对话串内容

按 **导出内容** → 选格式 / 范围 → 开始导出。

它会一篇一篇「自己点开」，等内容不再变动后，把右边对话区的文字抓下来，
最后把全部篇数存成一个文件（不是一篇一个文件）。

| 格式 | 输出样子 |
| --- | --- |
| 纯文本 | 每篇一个【编号】标题，段落之间空一行，标题前后空两行，项目缩两格 |
| JSON | `{ threads: [{ title, url, text }] }`，好写程序处理 |

**来源卡片与旁边的广告都不收**：Google 会在回答尾巴挂一排「来源」卡片（favicon + 网站名 + 标题 + 摘要），
右边那一栏偶尔还有赞助广告。那些对「只想看结论」的人没用，所以导出的文件里直接不会出现，只留回答本身。

判断方式是看「文字是不是几乎都落在一个外部链接里」——Google 的来源链接其实是跳转网址
（`www.google.com/url?q=…`），所以不能看到 google 域名就当成站内链接跳过；
有些版本没有 `<a>`、只用 `role="link"` 做的卡片也认得出来。
回答**正文里**的链接不会被误删（那段文字扣掉链接以后还有一大段话，就判定是正文）。

输出的样子大概长这样：

```
AI 模式 对话串导出
导出时间：2026/11/8 下午 12:13
篇数：3
来源：https://www.google.com/search?udm=50...

──────────────────────────────────────────────

【1】DSH Discord 模型交互接入

是的，DeepSeek Harness (DSH) 有对应的插件...


重点整理

重点一：先把需求拆成几个小步骤。

──────────────────────────────────────────────
```

**简体转繁体**：默认开着。有些人问 AI 模式时自己的问题就是简体，或回答里引用了简体原文，
打开之后整份文件不会混到简体字。不需要就把它取消勾选。

几个要注意的：

- 跑的时候**这个标签页要留在前台**，切到别的窗口会抓不到（浏览器会把后台标签页降速）
- 画面会一直跳，那是它在切换对话串，正常
- 每一篇会等到「真的讲完」才收手：文字安静约 1.2 秒后，**再确认一次**有没有继续长，
  还在长就继续等；所以长回答不会只抓到开头
- 长回答会先自动滚到底再滚回来，把还没画出来的段落逼出来
- 真的等到 40 秒还没停（例如一直在生成）才会硬收，log 会标 `⚠ 可能不完整` 提醒你那一篇要自己补看
- 长文之后会多留一点缓冲才点下一篇，避免页面还没收尾就被打断
- 连续导出多篇时，如果某一篇一时切不过去，它会**自己重试一次**（log 会出现 `↻ 重试一次`）
- 抓的是「画面上看得到的文字」，图片、图表、被收合的区块不会有
- 很长的对话如果 Google 有做延迟加载，可能只抓到已加载的那一段
- 抓错区块（例如抓到整页、或抓到整个侧边栏）就按设置窗口里的 **内容校准**，
  点一下右边的对话区，它之后就只抓那一块

> 找对话区不用先校准：它会从侧边栏右边多点采样，取「最大但不含侧边栏」的那个容器，
> 所以 `main`、`#main`、全宽 wrapper 都吃得下。真的抓错了再用「内容校准」覆盖。

## 抓不到列表怎么办

Google 的 class 名称是每天在变的，所以这个扩展不靠 class，靠的是：

1. 找每一行右边那颗 `aria-label` 含「更多选项 / More options」的按钮，往上回推整行
2. 找不到就用结构猜（左侧、宽度、高度、垂直连续、排除导航项）
3. 都不行 → 用你校准的结果

**校准**：按面板的「校准」→ 页面上方会出现蓝色提示 → 用鼠标点左侧任何 **一个** 对话串。

校准会优先记住那一行的 **class**（同一份 DOM 里每一行都共用），记不到才退回「父层路径 + 标签」。
如果记到的东西只认得出 1 行，扩展会**自己丢掉**这个校准、改回自动检测，不会卡在坏掉的状态。

## 隐私

- 只读你眼前这个页面的 DOM，只在你按下去之后才模拟点击
- 没有任何 `fetch` 到外部服务器，没有分析、没有遥测
- 设置只存在 `chrome.storage.local`
- 不读 cookie、不读 token、不碰你的密码

---

## 已知限制

- **删除是真的删**，Google 没有 API 可以复原，扩展也救不回来
- 导出内容不含图片与表格结构，只抓文字
- 导出的文件不含「来源」卡片与旁边的广告；如果你其实需要那些网址，得自己另外记
- 导出时会切换对话串，结束后画面会停在最后抓的那一篇
- 简转繁是「单字对照」为主，少数一字多形的字（例如「干」/「乾」）靠常见词表补，
  罕见用法还是可能挑错字
- Google 改版就可能失效 → 这时按「诊断」把结果贴出来，改选择器就好
- 只支持「最近的对话」那种列表；不处理 Google 账号里的「全部活动」
- 需要你自己已登录；扩展不会帮你登录
- 不要跟那个付费扩展同时开，两个都会在页面上画勾选框

## 文件结构

```
manifest.json          MV3 设置
content/content.js     全部逻辑（检测、勾选框、删除引擎、导出、面板）
content/i18n.js        界面三语字符串
content/s2t.js         简→繁 对照表（OpenCC STCharacters 精简版）
popup/                 工具栏弹出窗口
icons/                 图标
test/run-test.js       端到端测试（真的开 Chrome 跑）
test/aimode/fixture.html  测试用的假 AI 模式页面
test/shot.js           截图用
test/make-icons.py     重新生成图标
test/build-s2t.js      重新生成简繁对照表
```

## 开发

```bash
node test/run-test.js   # 用 headless Chrome 跑完整流程（加载 → 校准 → 单删 → 批量删）
node test/shot.js       # 生成 preview.png
py test/make-icons.py   # 重画图标
```

测试会把扩展复制到暂存文件夹、把 match 改成 `http://127.0.0.1/*`，
再用 CDP 的 `Extensions.loadUnpacked` 加载（`--load-extension` 在 headless 不可靠）。
